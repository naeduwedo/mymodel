# ADR-009 — 严格、强类型的配置，并约束路径范围

**状态：** 已接受（Task 1 的实现决策）

## 上下文

spec §11 要求每个选项都有带默认值的 schema、范围校验和 UI 帮助；§9.3 要求文件路径被规范化并限制在配置好的目录内。手写的 `serde_json::Value` 配置会把这两件事做错：拼写错误被静默忽略，而 `paths.models` 里的一个 `../` 就能把 40 GB 的下载重定向到用户主目录。

## 决策

- 配置是一个强类型的 Rust 结构，带 `#[serde(deny_unknown_fields)]` —— 未知键即错误，因为一个被静默忽略的设置就是撒谎。
- 默认值就是规范的示例值，并由一个测试断言。
- 校验拆分为 `check()`（返回全部发现，供 UI 使用）和 `validate()`（遇错误即失败），这样设置页面可以一次显示所有问题。
- 每个配置的目录都相对同一个数据根解析；若解析结果落在其外，则以 `PathEscape` 拒绝。
- 安全默认值在 schema 中强制执行：非回环的 API 绑定需要令牌认证，否则配置无效。

## 后果

- 升级选项集是一次带测试的代码改动，而不是对配置文件迁移的猜测。
- 想把数据放在别处的用户会得到一个明确的错误，告知路径必须留在数据根内，而不是被静默写入某个随机位置。
- Task 2 的 `settings` 表可以存储按 key 的覆盖值，因为键集合是静态已知的。
