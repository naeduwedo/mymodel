# ADR-008 — 有界、强类型、可重放的事件总线

**状态：** 已接受（Task 1 的实现决策）

## 上下文

每个 UI 都需要状态变化的实时流（生命周期、工作进程、下载、内存压力）。朴素的设计 —— 无界通道或共享的可变快照 —— 要么在某个 UI 变慢时无限制增长，要么丢失渲染一致状态所需的顺序。

## 决策

`gguf-engine-event-bus` 提供：

- **强类型载荷**（`EventPayload`），绝不是字符串化的消息；
- 每订阅者一个**有界**队列：慢的 UI 会丢事件，且丢失在两端都有计数（`BusStats::dropped`、`EventSubscriber::lagged`），而不是阻塞推理路径或撑大内存；
- 一个**单调的 `seq`** 加上一个有界重放环，使重连的 UI 可以用 `replay_after(seq)` 续接并检测空洞；
- UTC 时间戳与关联 id，用于任务范围的事件。

## 后果

- 发布者从不在 UI 上阻塞。它们可能收到 `Backpressure`，该情况被记录并计数，而不会作为致命错误向上传播。
- UI 的契约是“状态是权威，事件是增量”：错过事件的客户端可以重新读取健康/状态并继续。
- 重放环在内存上是有界的（`replay_limit`），所以它是便利手段，不是持久化机制；持久历史是数据库的关注点（Task 2）。
