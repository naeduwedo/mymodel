# ADR-014 — GGUF 解析：有界前缀读取，不用 mmap

**状态：** 已接受（Task 5 的实现决策）

## 背景

规格 §7.1 要求一个只读的 GGUF 解析器，能够抵御畸形文件：整数溢出、越界偏移、荒谬的长度、
重复键和非法字符串。最显而易见的实现——把文件 `mmap` 进来再按偏移索引——有一个隐蔽的
失效模式：文件在映射之后被截断或缩小，解析器一旦触及超出当前文件大小的页，就会触发
`SIGBUS`（不是可捕获的错误）。这会杀死进程，而这恰恰是处理不可信输入的解析器绝对不能做的事。

## 决策

只读取文件开头部分：

- 头部、元数据和张量表都位于张量载荷之前，因此一次有界前缀读取（`HEADER_READ_LIMIT` = 256 MiB）
  就包含了解析器所需的一切；
- 因此检查一个 100 GB 的模型只需几 MB 内存，既没有 `mmap`，也没有 `unsafe`，也没有 `SIGBUS`；
- 每次读取都经过一个无法越出缓冲区的游标；来自文件的每个长度都在为任何东西分配空间*之前*
  对照 `Limits` 检查；
- 张量边界会拿真实文件长度（随前缀一并传入）来校验，因此指向文件末尾之外的张量即使其字节
  从未被读取，也会被拒绝。

## 后果

- 解析器中任何地方都没有 **`unsafe`**；工作区级的禁令依然成立。
- 畸形输入产生带字节偏移的错误，绝不会 panic。
- 无法识别的张量类型保留其数字 id，并报告为 `unknown(N)`，这样兼容性报告不会把“类型 27”
  误当成已知的量化类型。
- 大端文件（历史上的 `-be` 量化）会被如实标明，而不是报出一个荒谬的版本号——这是在真实文件上
  发现的。

## 验证

- 35 个单元测试：20 个合成的畸形用例（错误的 magic、截断的头部、2^40 的元数据条目数、重复键、
  越界张量、溢出、错误对齐、未知类型、深层数组嵌套），外加一个必须运行的真实文件测试
  （没有样本文件时它会明确失败）。
- 一次真实的网络拉取 + 检查会解析下载得到的文件，并报告它真实的架构，而不是猜测。
